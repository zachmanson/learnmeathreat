## Phase Goal

**As a** reader working through a math-heavy explainer, **I want to** see equations typeset properly, link directly to any section, and read code samples with syntax highlighting, **so that** the technical content is actually legible rather than a wall of raw LaTeX.

<objective>
Turn the seed post's raw Markdown source into properly rendered technical prose: build-time KaTeX math, stable clickable heading anchors, and Shiki-highlighted code blocks — all with zero client-side JavaScript and no flash of unrendered content.

Purpose: This is the requirement that makes the entire project viable. A quantum-computing explainer series where `$\lambda$` renders as literal dollar-sign text is not shippable. This plan is deliberately separated from 01-01 because Astro 7's markdown processor change (see below) is the single highest-risk piece of the phase and deserves its own focused execution and its own verification pass.

Output: `markdown.processor` wired to `unified()` from `@astrojs/markdown-remark`, KaTeX stylesheet loaded, `prose.css` implementing the UI-SPEC's anchor/math/code contract, and a second automated test suite asserting the rendered output.

CRITICAL — do not use pre-Astro-7 tutorials. Astro 7 replaced the default Markdown processor with Sätteri (Rust-based). The flat `markdown.remarkPlugins` / `markdown.rehypePlugins` config keys still parse without error but no longer execute plugins. A build configured that way SUCCEEDS and silently emits raw `$...$` text. See RESEARCH Pitfall 2 and "State of the Art".
</objective>

<interfaces>
The exact Astro 7 processor config shape (RESEARCH Pattern 1, sourced from
docs.astro.build/en/guides/markdown-content/ and withastro/astro commit f732f3c):

```javascript
import { defineConfig } from 'astro/config';
import { unified } from '@astrojs/markdown-remark';
import remarkMath from 'remark-math';
import rehypeKatex from 'rehype-katex';
import rehypeSlug from 'rehype-slug';
import rehypeAutolinkHeadings from 'rehype-autolink-headings';
import { h } from 'hastscript';

export default defineConfig({
  markdown: {
    processor: unified({
      remarkPlugins: [remarkMath],
      rehypePlugins: [
        rehypeKatex,
        rehypeSlug,                 // MUST run before autolink-headings - Pitfall 1
        [rehypeAutolinkHeadings, {
          behavior: 'prepend',
          content: h('span.heading-anchor', '#'),
          properties: { ariaHidden: 'true', tabIndex: -1, class: 'heading-anchor-link' },
        }],
      ],
    }),
  },
});
```

Shiki is Astro's built-in default highlighter and needs no plugin and no package —
do not add prism, highlight.js, or any client-side highlighter.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Markdown source to rehype/KaTeX rendering | LaTeX strings from post files are transformed into HTML at build time |
| npm registry to local build | remark/rehype/KaTeX plugin code executes during `astro build` |

No client-to-server boundary exists. Output remains fully static pre-rendered HTML with zero client JavaScript.

| Threat ID | Category | Component | Disposition | Mitigation Plan |
