# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — plain Astro `.astro` components + semantic HTML, no React/Radix/component-kit |
| Icon library | none — Phase 1 needs no icons (nav is text links, heading anchors use a plain `#` glyph, not an icon font/SVG set) |
| Font | system font stack for both body and headings in Phase 1 (see Typography). No custom webfont is loaded yet — DSGN-02's distinct monospace/serif accent header font is explicitly Phase 2 scope (roadmap: Phase 2 "Visual Design & Theming"). Loading a placeholder custom font now would mean redoing font-loading config in Phase 2 for no benefit. |

**Why no shadcn/component library:** This project is a plain Astro static site (no React/Next/Vite in the stack — see PROJECT.md tech stack). PROJECT.md explicitly rejects "themed starter" aesthetics and component-kit overhead in favor of "lean and hand-built... text is the star," and the roadmap's zero-JS-by-default constraint means Phase 1 should ship as close to raw semantic HTML + a small hand-written stylesheet as possible. The shadcn initialization gate only applies to React/Next.js/Vite stacks, so it is skipped here by design, not by omission.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Tag chip inline padding, gap between icon-less inline elements |
| sm | 8px | Gap between post meta items (date · tags), nav link gaps |
| md | 16px | Default paragraph/element spacing within post body |
| lg | 24px | Space between post list items on homepage |
| xl | 32px | Space between nav bar and page content, section padding |
| 2xl | 48px | Space above/below page title (post title, "About" title) |
| 3xl | 64px | Top-level page margin (space before nav / after footer) |

Exceptions: none. Phase 1 has no icon-only touch targets (nav is text links; no icon buttons ship this phase).

## Typography

Phase 1 uses the OS default font stack (`system-ui, -apple-system, "Segoe UI", Roboto, sans-serif` for body/headings, `ui-monospace, "SFMono-Regular", Consolas, monospace` for code) rather than a custom webfont. Rationale: DSGN-02 (distinct monospace/serif accent header font) is explicitly a Phase 2 requirement — picking a font now would be redone next phase. Math (KaTeX) renders in its own required math font per CONT-02 ("in the same font as body text" refers to surrounding prose flow, not literally overriding KaTeX's glyphs — KaTeX ships its own font by necessity for correct glyph rendering).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 18px | 400 (regular) | 1.6 |
| Label (meta: date, tags, nav) | 14px | 400 (regular) | 1.4 |
| Heading (h2/h3 in post body) | 24px | 600 (semibold) | 1.25 |
| Display (page title: post title, "About", homepage intro) | 32px | 600 (semibold) | 1.2 |

Only 2 weights declared (400, 600) — matches the design-contract limit and keeps the base stylesheet minimal, consistent with "hand-built, not templated."

Code blocks: 15px, `ui-monospace` stack, line-height 1.5, no wrap — horizontal scroll on overflow (required for mobile legibility of long code lines, per DSGN-04 which lands in Phase 2 but should not be architecturally precluded now).

## Color

Phase 1 ships a single light surface only — DSGN-03 (light/dark toggle) is explicitly Phase 2 scope. Building a real dark theme now would be thrown away/redone once Phase 2 defines the actual palette; shipping a placeholder toggle would create false affordance. Phase 1's job is legible, unstyled-but-not-ugly text on a plain background.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | #FFFFFF | Page background |
| Secondary (30%) | #F4F4F5 | Code block background, subtle nav/footer separation, tag chip background |
| Accent (10%) | #1D4ED8 | Links only: nav links, post title links on homepage, heading anchor `#` on hover, in-body links |
| Destructive | not applicable | No destructive actions exist in Phase 1 (no forms, no delete affordances — read-only content site) |

Body text color: #18181B (near-black, not pure black — softer on the eyes, standard practice for long-form reading). Muted text (meta/labels): #71717A.

Accent reserved for: nav links (Home/About), post title link on the homepage list, in-body prose links, and the heading anchor `#` glyph (shown only on hover/focus, not by default — keeps headings visually quiet until interacted with).

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Post title itself is the link (no separate "Read more" button) — homepage list items link via their title, matching learnmeabitcoin.com's understated convention referenced in PROJECT.md. If a supplementary affordance is wanted, use "Read post →" as trailing text, not a button. |
| Empty state heading | "No posts yet." |
| Empty state body | "Check back soon — the first post is on its way." (Edge case only: real posts ship as part of Phase 1's own success criteria, so this should not normally be visible in production, but must not break if the collection is briefly empty during setup.) |
| Error state | Not applicable as a runtime UI — Phase 1 has no user input/forms. Frontmatter schema violations (CONT-01) fail loudly at **build time** via Astro's Content Collections Zod validation, surfaced in the terminal/CI log, not as an in-browser error state for readers. |
| Destructive confirmation | Not applicable — no destructive actions in Phase 1 (read-only content site, no admin UI per PROJECT.md's explicit "no web-based CMS" decision). |

## Interaction Contract (Phase-1-specific, beyond template defaults)

- **Heading anchors (CONT-03):** Every post heading (h2+) gets a stable `id` slug. On hover/focus of the heading, a `#` glyph appears immediately before the heading text, colored with the Accent value, linking to `#that-id`. Not visible by default — avoids visual clutter on a text-first page.
- **Code blocks (CONT-04):** Syntax-highlighted via Astro's built-in Shiki integration (build-time, no client JS, consistent with the zero-JS-by-default constraint). Background uses Secondary color; block gets `sm` (8px) padding minimum, `md` (16px) horizontal padding; overflow-x scrolls rather than wraps.
- **Math (CONT-02):** Rendered at build time via remark-math + rehype-katex (already the confirmed stack choice in PROJECT.md) — no client-side JS, no flash of unrendered `$...$` text. Inline math sits within body text at Body size; block math (`$$...$$`) is centered with `lg` (24px) vertical margin.
- **Nav (PAGE-04):** Simple horizontal text nav — site title (links home) on the left, "Home" / "About" links on the right (or below site title on narrow viewports — exact mobile behavior is Phase 2/DSGN-04 territory, but nav must not visually break at narrow widths in Phase 1: stack vertically or wrap, don't overflow).
- **Homepage post list (PAGE-01):** Reverse-chronological. Each item: Display-adjacent title link (use Heading size, not full Display size, to keep list items compact — 24px/600), date + tags as Label-size muted meta line below title, excerpt as Body-size text below that. `lg` (24px) gap between items.
