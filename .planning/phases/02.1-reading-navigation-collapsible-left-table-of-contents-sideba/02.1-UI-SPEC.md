# Phase 02.1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none — plain Astro `.astro` components + semantic HTML (`<details>`/`<summary>`, `<nav>`), same posture as Phase 1/2 |
| Icon library | none — mobile left-sidebar toggle uses an inline hand-drawn SVG glyph matching `ThemeToggle.astro`'s existing sun/moon SVG pattern (stroke-based, `currentColor`), not an icon font/library |
| Font | No new fonts. Sidebar chrome (chapter labels, post links, "on this page" links) uses the existing system-ui body stack at Label size (14px/400, per Phase 1 Typography). The IBM Plex Mono heading accent (Phase 2 D-01/D-02) does **not** extend to sidebar nav text — sidebars are navigation chrome, not headings, matching how `.site-header nav` already stays on the system font. |

**Why no shadcn/component library:** Confirmed via `components.json` absence — this remains a plain Astro static site (no React/Next/Vite), consistent with Phase 1's established rationale. This phase adds zero new runtime UI dependencies (per 02.1-RESEARCH.md "Standard Stack" — only `unist-util-visit`, a build-time AST utility, not a UI library).

## Spacing Scale

Reuses Phase 1's declared 8-point scale (`.planning/phases/01-scaffolding-core-content-pipeline/01-UI-SPEC.md`) — no new tokens introduced.

| Token | Value | Usage in this phase |
|-------|-------|-------|
| xs | 4px | Gap between a heading-depth indent step (h3 sub-items nested under h2 in both sidebars) |
| sm | 8px | Gap between stacked links within a chapter/section list; chapter `<summary>` internal padding |
| md | 16px | Padding inside sidebar `<nav>` container; gap between right-sidebar heading and its first link |
| lg | 24px | Vertical gap between chapters in the left sidebar |
| xl | 32px | `column-gap` between the three grid columns (left sidebar / content / right sidebar) — per 02.1-RESEARCH.md Pattern 6 |
| 2xl, 3xl | 48px, 64px | Not used by this phase's new components |

**Exceptions:** The mobile left-sidebar toggle button reuses the existing **44×44px sanctioned touch-target exception** (established in `src/styles/global.css` for `#theme-toggle`) — same rationale, same size, same non-accent (`--muted`/`--text`) coloring so it doesn't compete with the 10% accent budget.

## Typography

Reuses Phase 1's declared type scale — no new sizes or weights introduced (stays within the 4-size/2-weight limit).

| Role | Size | Weight | Line Height | Used for |
|------|------|--------|-------------|----------|
| Label | 14px | 400 | 1.4 | Left sidebar post links, right sidebar "on this page" links (default/inactive state) — matches existing `.site-header nav` sizing exactly |
| Label (chapter title) | 14px | 600 | 1.4 | Left sidebar `<summary>` chapter names — bolder than post links so the chapter groups scan as headers within the sidebar, using the existing 600 weight (no third weight added) |
| Label (active state) | 14px | 600 | 1.4 | Right-sidebar active/in-view link (D-09: bold + accent color, no border/bar) and left-sidebar current-post link (`aria-current="page"`) — same weight bump, colored `--accent` |
| Body | 18px/1.6 | 400 | — | Unchanged — post content itself; sidebars never resize body text |

No Display-size or Heading-size (24px/32px) text appears in either sidebar — sidebars are navigation chrome, deliberately quieter than page content, consistent with Phase 1's "headings never compete with Display" visual-anchor rule.

## Color

Reuses Phase 1/2's existing 5-role token set (`--bg`, `--surface`, `--accent`, `--text`, `--muted`) from `src/styles/global.css` and its `[data-theme="dark"]` override block — **no new color tokens** are introduced by this phase, per Phase 2 CONTEXT.md's explicit instruction that sidebars "must work in both themes using the existing token set, not new colors."

| Role | Value (light) | Value (dark) | Usage |
|------|----------|----------|-------|
| Dominant (60%) | `--bg` #FFFFFF | #1E1E1E | Sidebar background — sidebars sit directly on the page background (no boxed/card treatment), keeping the "text is the star" minimal posture |
| Secondary (30%) | `--surface` #F4F4F5 | #2A2A2A | Not used as a sidebar background (avoids introducing a new "boxed panel" visual not present elsewhere on the site); reserved if a future hover-state background is needed |
| Accent (10%) | `--accent` #1D4ED8 | #34D399 | Reserved for exactly two things in this phase: (1) the right-sidebar's currently-in-view heading link, and (2) the left-sidebar's currently-viewed post link (`aria-current="page"`). Both also get the 600-weight bump — never accent color alone without the weight change, and never a border/background/indicator bar (explicit per D-09) |
| Destructive | not applicable | not applicable | No destructive actions in this phase (read-only navigation) |

Default (inactive) link/text color for both sidebars: `--muted` (matches existing `.site-header nav a` convention — nav-level links are muted by default, not full `--text` black, until interacted with). Hover/focus state: `--text` (also matches `.site-header nav #theme-toggle:hover` convention already established).

Chapter `<summary>` disclosure triangle (native `::marker`): `--muted`, no accent — it's a structural affordance, not a link.

**Accent reserved for:** the right-sidebar's active/in-view section link (D-09) and the left-sidebar's current-post link only. Nothing else in either sidebar uses accent — chapter titles, inactive post links, and inactive outline links all stay `--muted`/`--text`, preserving the existing "accent = interacted-with or you-are-here" convention from Phase 1.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Left sidebar landmark label | `aria-label="Site contents"` on the `<nav>` (screen-reader only — no visible sidebar title, since the accordion's chapter names already communicate structure; avoids adding a redundant "Table of Contents" heading above them) |
| Right sidebar heading | **"On this page"** — visible heading atop the sidebar, plain text (not a link), Label size/600 weight. Directly matches the mental model in CONTEXT.md's own framing ("the right 'on this page' gives the layout of what's on the current page") |
| Chapter fallback name (post has no tags) | **"Uncategorized"** — plain, honest label per 02.1-RESEARCH.md Pattern 3's `tags[0] ?? 'Uncategorized'` fallback. Not expected to appear once the user tags their first posts, but must not break/look broken if it does |
| Mobile left-sidebar toggle — closed state | `aria-label="Show contents"`, visible button text/icon: a simple list/menu-style SVG glyph (no visible text label needed at 44×44px — icon-only, same pattern as `ThemeToggle.astro`'s icon-only button) |
| Mobile left-sidebar toggle — open state | `aria-label="Hide contents"` (label swaps on toggle, same pattern as `ThemeToggle.astro`'s `updateThemeToggleLabel()`) |
| Empty state | Not applicable — both sidebars are populated at build time from real content (`getCollection('posts')`, current post's own `headings`). D-10 already handles the one legitimate "nothing to show" case (fewer than 2 headings) by hiding the right sidebar entirely rather than showing empty-state copy — no post-count-zero case exists since the left sidebar only renders on individual post pages, which by definition means at least one post exists |
| Error state | Not applicable — no runtime user input. A post with malformed/missing tags fails the schema-validation build-time error already established in Phase 1's Content Collections contract, not a new in-browser error state |
| Destructive confirmation | Not applicable — no destructive actions in this phase |

## Interaction Contract (Phase-02.1-specific, beyond template defaults)

- **Anchor scheme (D-01/D-02):** Headings h2–h6 (h1 excluded) get sequential `id="h-1"`, `id="h-2"`, ... in document order at build time. The existing hover-reveal `#` anchor-link behavior (`.heading-anchor-link`, `.heading-anchor` in `prose.css`) is unchanged — only the underlying `href`/`id` values change from text-slugs to `#h-N`. No new CSS needed for this part.
- **Left sidebar (D-03–D-07):** Always visible on desktop (>900px), positioned in the grid's left column. Built from `<details open={isCurrentChapter}><summary>{chapterName}</summary><ul>...</ul></details>` per chapter — zero JS, native browser disclosure widget (02.1-RESEARCH.md Pattern 4's recommended default, consistent with this site's zero-JS-by-default posture). Only the chapter containing the currently-viewed post starts expanded; all others start collapsed. Appears only on `/posts/[slug]` pages — absent from homepage and `/about`.
- **Left sidebar mobile toggle (<900px):** A single 44×44px icon button (Claude's Discretion per CONTEXT.md, using `ThemeToggle.astro`'s icon-button pattern as the model) shows/hides the sidebar as a full-width block stacked above the article — no slide-in drawer, no overlay, no focus-trap (avoids the added accessibility surface a drawer pattern would require, per 02.1-RESEARCH.md Open Question 2's recommendation).
- **Chapter/post ordering (Claude's Discretion, A1/A2 in RESEARCH.md):** Chapters keyed by each post's first tag (`tags[0]`) — a post belongs to exactly one chapter, avoiding duplicate listings. Within a chapter, posts sort oldest-first (book-chapter reading order). Both are explicitly flagged as low-confidence defaults to revisit once 3+ real chapters exist — not user-locked.
- **Right sidebar (D-08–D-11):** Renders only when the current post has ≥2 headings at depth 2 or 3 (nested `<ul>`, h3 indented under its preceding h2 using the `xs` token). Populated directly from Astro's `render(post).headings` (already carrying the `h-N` ids per Pattern 2) — no separate heading-extraction step. Hidden entirely (not just collapsed) below 900px — no mobile toggle for this sidebar (D-11).
- **Scroll-spy (D-09, Pattern 5):** `IntersectionObserver` (`rootMargin: '0px 0px -80% 0px'`) toggles an `is-active` class on the matching right-sidebar link as each heading crosses the "reading position" band near the top of the viewport. Active styling is class-only (weight 600 + `--accent` color) — no layout shift, no border/indicator bar. Script lives inside `RightNavSidebar.astro` itself (not `Layout.astro`'s `<head>`), following `ThemeToggle.astro`'s placement pattern so queried elements already exist in the DOM.
- **Click-to-scroll behavior:** Right-sidebar link clicks smooth-scroll to the target heading by default; respects `prefers-reduced-motion` (falls back to instant jump) — Claude's Discretion per CONTEXT.md, standard accessible default.
- **Layout (D-12/D-13, Pattern 6):** A new `.post-layout` CSS Grid wrapper (`grid-template-columns: 1fr min(68ch, 100%) 1fr`, `grid-template-areas: "left content right"`) wraps `<article>` + both sidebars inside `[slug].astro`. The existing `.site-header, main { max-width: 68ch; margin: 0 auto }` rule in `global.css` stays untouched; a more specific `main .post-layout { max-width: ...; margin: 0 auto }` rule (beats the 68ch rule on specificity, no `!important`) governs the wider 3-column width on post pages only. Below 900px, `grid-template-columns: 1fr` / `grid-template-areas: "content"` collapses to the existing single-column mobile layout, with both sidebars hidden per D-05/D-11. Exact side-column width/gap values are a first-draft per Pattern 6 — flagged in RESEARCH.md Open Question 1 as needing a manual visual check at 1024px/1440px/ultrawide during implementation, not assumed correct from CSS math alone.
