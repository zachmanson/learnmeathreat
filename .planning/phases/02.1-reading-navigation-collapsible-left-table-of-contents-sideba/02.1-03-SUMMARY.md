# Phase 02.1 Plan 03: Right Nav Sidebar + Human Verification Summary

**Built the right "On this page" outline sidebar with IntersectionObserver scroll-spy, wired it into the post grid behind a 2-heading gate, and closed the phase after fixing two bugs surfaced during human visual verification: an invisible-sidebars layout bug and a stray "#" in outline labels.**

## Performance

- **Duration:** ~65 min total (24 min for the 3 automated tasks; remainder was checkpoint-triggered debugging with the user)
- **Tasks:** 4 (3 automated + 1 human-verify checkpoint)
- **Files modified:** 6 (1 created, 5 modified across the plan + 2 post-checkpoint fixes)

## Accomplishments

- `RightNavSidebar.astro`: nested h2/h3 outline built directly from `render(post).headings` (no second heading-collection pass), IntersectionObserver scroll-spy toggling `.is-active`, reduced-motion-aware smooth-scroll click handler, `IntersectionObserver in window` guard
- `[slug].astro`: destructures `headings`, filters to depth 2/3 as `outlineHeadings`, renders `RightNavSidebar` only when `outlineHeadings.length >= 2` (D-10)
- `tests/reading-navigation.test.mjs`: 5 new tests (7-11) locking outline rendering, anchor/id consistency, depth filtering, the D-10 source gate, and the zero-dependency scroll-spy
- **Checkpoint bug #1 (layout):** `main`'s own `max-width: 68ch` was capping `.post-layout`'s actual rendered width regardless of the child's own larger `max-width` — a block element with `width: auto` is sized by its containing block, not its own `max-width`. Both sidebar grid columns computed to 0px. Fixed by changing the override in `global.css` to target `main:has(.post-layout)` directly instead of `main .post-layout`. Verified live via Playwright: computed width went from 660px (broken) to 1204px (fixed); confirmed home/about unaffected (still 68ch).
- **Checkpoint bug #2 (content):** Right-sidebar outline labels showed a leading "#" (e.g. "#What Bitcoin's Public Keys Are Protecting"). Root cause: `rehypeAutolinkHeadings` prepends a visible `#` anchor span (no `aria-hidden`) as the heading's first child, and Astro's heading-text collector reads the final rehype tree, so `headings[].text` arrives with that "#" baked in. Fixed by stripping a leading `#` in `RightNavSidebar.astro` at the point the label is rendered, rather than touching the shared anchor markup other features (hover-reveal permalinks) depend on.

## Deviations from Plan

### Post-checkpoint fixes (not part of the original 3 automated tasks)

**1. [Bug] Invisible sidebars at desktop widths — layout containment bug**
- **Found during:** Human visual verification (Task 4 checkpoint)
- **Root cause:** `main .post-layout { max-width: ... }` in `global.css` (added in plan 02.1-02) targeted the child, but `main`'s own unmodified `max-width: 68ch` rule still constrained the containing block `.post-layout` is sized against — a block child with `width: auto` is sized by its containing block, not by its own `max-width`. Confirmed live: `main` computed width stayed 660px regardless of `.post-layout`'s 1204px `max-width`; left/right grid columns rendered at 0px.
- **Fix:** Changed the selector to `main:has(.post-layout)` so the override lands on `main` itself. Verified fixed (1204px, both sidebars 240px) and that home/about are unaffected (still 68ch).
- **Commit:** `d0f1ea1`

**2. [Bug] Leading "#" in right-sidebar outline text**
- **Found during:** Human visual verification (Task 4 checkpoint)
- **Root cause:** `rehypeAutolinkHeadings`'s prepended `#` anchor span has no `aria-hidden`, so Astro's heading-text collector (which reads the final rehype tree) includes it in `headings[].text`.
- **Fix:** Strip a leading `#` in `RightNavSidebar.astro` where the label is rendered — the only consumer of `headings[].text` for display.
- **Commit:** `fbeb9f0`

### Environment note (not a plan deviation)

During checkpoint debugging, `rm -rf dist .astro node_modules/.astro` was run twice while the `npm run dev` server was still live, which left it serving a stale content-collection cache (404 on the post route until restarted). Not a code defect — noted here in case a future session sees an unexplained dev-server 404 after a cache wipe: restart the dev server after clearing `.astro`, don't wipe it live.
