## Anchor hash scheme

| Option | Description | Selected |
|--------|-------------|----------|
| Sequential numeric (#h-1, #h-2...) | Shortest possible, fully stable (position-based, immune to text edits). Not self-descriptive in a shared URL. | ✓ |
| Frontmatter/inline explicit IDs | Author sets a short id per heading in Markdown. Fully stable and self-descriptive, but manual authoring overhead. | |
| Truncated slug from heading text | Shorter than today but NOT stable — still breaks on rewording. | |

**User's choice:** Sequential numeric (#h-1, #h-2...)

| Option | Description | Selected |
|--------|-------------|----------|
| All headings except h1, in document order | h2/h3 share one sequence. | ✓ |
| Only h2 (section headings) | h3s don't get their own anchor/ID. | |

**User's choice:** All headings except h1, in document order

## Left ToC sidebar

**Scope correction:** User clarified mid-discussion that the left sidebar is site-wide navigation of ALL posts on the site (book-style table of contents), not a per-page heading outline. "The ToC is for the contents of like everything I have posted on the site not what's on the current page. The right 'on this page' gives the layout of what's on the current page." This overrode the initial framing where an earlier question ("Which heading levels appear in the left ToC list?") had assumed per-page headings — that answer (h2 only) was discarded and re-asked for the right sidebar instead.

**User's choice:** Grouped by tag/category, acting as chapters. "I will tag posts to be in some categories which would be like chapters and then the posts themselves will be inside those chapters."

| Option | Description | Selected |
