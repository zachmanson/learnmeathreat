**Core transform pattern** (lines 25-35, the exported function):
```javascript
export function rehypeSequentialIds() {
  return (tree) => {
    let counter = 0;                       // <-- MUST be inside the returned closure
    visit(tree, 'element', (node) => {
      if (!HEADING_TAGS.has(node.tagName)) return;
      counter += 1;
      node.properties = node.properties || {};
      node.properties.id = `h-${counter}`;
    });
  };
}
```
**Critical scoping rule to copy exactly:** the per-file state (`counter` here, analogous to `figureCounter` in the new figure plugin) must be declared as the first line **inside** the arrow function returned by the exported factory — never in the factory's outer scope. `unified().use(plugin)` calls the factory once per pipeline construction, but the returned transformer runs once per file. **Naming convention:** plugin is a named export (`export function pluginName()`), not a default export, matching `rehypeSequentialIds`. Follow this for `remarkCiteTranslate` and `remarkDirectiveToHast`.

**Target shape for the new file** (per RESEARCH.md Pattern 2, verified consistent with this analog's style):
```javascript
import { visit } from 'unist-util-visit';

const CITE_PATTERN = /\\cite\{([^}]+)\}/g;

export function remarkCiteTranslate() {
  return (tree) => {
    visit(tree, 'text', (node) => {
      if (CITE_PATTERN.test(node.value)) {
        CITE_PATTERN.lastIndex = 0; // reset global regex state before reuse
        node.value = node.value.replace(CITE_PATTERN, '[@$1]');
      }
    });
  };
}
```

### `src/lib/remark-directive-to-hast.mjs` (utility, transform)

**Analog:** `src/lib/rehype-sequential-ids.mjs` (same file as above) + the official `remark-directive` README pattern (RESEARCH.md Code Examples section, verified via WebFetch)

**Imports pattern:** same as above, plus `hastscript`'s `h` helper (already resolves transitively per RESEARCH.md — only add an explicit `npm install hastscript` if a build error proves it doesn't resolve, same contingency documented for Phase 1).
```javascript
import { visit } from 'unist-util-visit';
import { h } from 'hastscript';
```

**Core pattern** — this single plugin must handle BOTH the callout/definition directive names AND the figure leaf directive, per RESEARCH.md's explicit "one implementation serving two content requirements" framing (D-09/D-11 share one mechanism):
```javascript
const CALLOUT_NAMES = new Set(['note', 'warning', 'tip', 'definition']);

export function remarkDirectiveToHast() {
  return (tree) => {
    let figureCounter = 0; // per-file scoping — copy rehype-sequential-ids.mjs's rule exactly

    visit(tree, (node) => {
      if (node.type !== 'containerDirective' && node.type !== 'leafDirective') return;

      if (CALLOUT_NAMES.has(node.name)) {
        const data = node.data || (node.data = {});
        const hast = h('div', { class: `callout callout-${node.name}` });
        data.hName = hast.tagName;
        data.hProperties = hast.properties;
        return;
      }

      if (node.name === 'figure' && node.type === 'leafDirective') {
        figureCounter += 1;
        const { src, alt = '' } = node.attributes || {};
        const isSvg = /\.svg$/i.test(src || '');
        const data = node.data || (node.data = {});
        data.hName = 'figure';
        data.hProperties = { class: 'content-figure' };
        node.children = [
          { type: 'element', data: { hName: 'img', hProperties: {
              src, alt, class: isSvg ? 'invertible' : undefined, loading: 'lazy',
            } }, children: [] },
          { type: 'element', data: { hName: 'figcaption' },
            children: [{ type: 'text', value: `Figure ${figureCounter}: ` }, ...node.children] },
        ];
      }
    });
  };
}
```
(Source: RESEARCH.md Pattern 1, itself adapted from `github.com/remarkjs/remark-directive`'s own README "Example: rendering directives" section.)

**Pipeline-order requirement to document in the header comment** (copy this style of note from `rehype-sequential-ids.mjs` lines 16-19): this plugin MUST run after `remarkDirective` in `remarkPlugins` and before Astro's internal remark-rehype conversion.

**Token reuse — do not invent new colors.** Every existing rule in this file and `global.css` draws exclusively from the 5 role-name custom properties defined once in `global.css` `:root` / `[data-theme="dark"]`:

--bg: #FFFFFF;      /* dark: #1E1E1E */

**CRITICAL — the `.prose` selector does not exist anywhere in this codebase.** RESEARCH.md Pitfall 2 (verified by grep against the real `src/` tree — zero matches for `.prose` as a class or selector) flags that `02.2-CONTEXT.md`'s references to ".prose content" and "prose.css scoped to .prose" describe an assumed convention that was never actually implemented. `prose.css`'s real existing selectors (`h2, h3`, `.katex`, `pre`, `code`, `.astro-code`) are **unscoped/global**, not nested under any wrapper class. ## Shared Patterns

### Custom transform plugin file structure
**Source:** `src/lib/rehype-sequential-ids.mjs` (entire file — canonical precedent)
**Apply to:** `src/lib/remark-cite-translate.mjs`, `src/lib/remark-directive-to-hast.mjs`
- Header block comment: states which CONTEXT.md decision(s) it implements, any accepted tradeoff, and any load-bearing pipeline-ordering constraint with a pointer to `astro.config.mjs`.
- Single named export, factory function returning a transformer: `export function pluginName() { return (tree) => { ... }; }`.
- Any per-file counter/state MUST be declared as the first statement inside the returned closure, never in the factory's outer scope (RESEARCH.md Pitfall 3).
- Uses `unist-util-visit`'s `visit(tree, [type,] callback)` — no other tree-walking library.

### CSS token discipline
**Source:** `src/styles/global.css` lines 1-28 (`:root` and `[data-theme="dark"]` blocks)
**Apply to:** `src/styles/prose.css` additions for figures, callouts, definitions
- Only 5 custom properties exist: `--bg`, `--surface`, `--accent`, `--text`, `--muted`. All new component styling must compose from these — no new color literals.
- Dark-mode overrides always take the form `[data-theme="dark"] .selector { ... }`, redeclaring only the properties that change.

### Requirement-ID-tagged CSS section comments
**Source:** `src/styles/prose.css` lines 8, 36, 57
**Apply to:** every new CSS section added in this phase
- Format: `/* --- Section Name (REQ-ID) --- */`, tying styling directly to a REQUIREMENTS.md id (planner must assign IDs per RESEARCH.md's suggested CONT-06..CONT-10 table before this can be filled in literally).

### Sequentially-numbered, message-rich test assertions
**Source:** `tests/theming.test.mjs` (all `test('N. description', () => {...})` blocks; helpers at lines 6-40; test 22 at lines 302-312)
**Apply to:** the rewritten test 22/22b, and all new tests in `tests/authoring-primitives.test.mjs`
- Every `assert.ok` call includes a descriptive failure message naming the requirement/decision id in parens and a human-readable reason.
- File-reading always goes through `readDistFile`/`readDistCss`-style helpers with ENOENT-aware error messages — never a bare `readFileSync`.
