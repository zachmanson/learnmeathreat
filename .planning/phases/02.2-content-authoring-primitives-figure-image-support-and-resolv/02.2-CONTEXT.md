## Phase Boundary

Adds four Markdown authoring primitives needed before real posts get written: (1) figure/image support with captions and auto-numbering, which requires resolving a direct conflict with Phase 2's existing "zero `<img>` tags in built output" DSGN-01 guard test; (2) LaTeX-style citation/bibliography support backed by a global `.bib` file; (3) callout/note admonition blocks (note/warning/tip); and (4) definition blocks for introducing jargon terms. This is an inserted phase (jumped ahead of Phase 3) — it touches the Markdown authoring/rendering pipeline only, not page layout, navigation, discovery, or deployment. No real post content exists yet; this phase is purely about the authoring primitives real posts will need.

<decisions>
## Implementation Decisions

### Figures/images (and DSGN-01 guard fix)
- **D-01:** Support **SVG** (vector) and **PNG/JPG** (raster) as figure formats. **No PDF authoring path** — browsers cannot render `<img src="x.pdf">`; PDF vector exports must be re-exported as SVG before being used as a figure.
- **D-02:** One `<Figure>` component: image + caption + auto-incrementing "Figure N" label, in the spirit of a LaTeX `figure` environment.
- **D-03:** SVG figures (black lines on transparent background, per the user's actual authoring habit) **auto-invert in dark mode** via a CSS `filter: invert(1)`-style rule — no dual image upload required. PNG/JPG raster images do **not** get inverted (would break color content or screenshots).
- **D-04:** DSGN-01's existing guard test — "no built page contains an `<img>` tag" (see `02-03-PLAN.md` Test 22 / `02-VERIFICATION.md`) — currently blocks ALL images, including legitimate content figures, and must be rewritten. The rewritten test should prohibit only marketing-style imagery (hero images, stock photos, decorative chrome) while explicitly allowing content-authored figures inside post body content. Exact rewrite mechanism (e.g., scoping the check to non-`.prose` regions of the built HTML) is Claude's discretion at planning time — the important constraint is that DSGN-01's actual intent (no stock photography / hero images / marketing-site styling) must still be enforced by *some* test, not simply deleted.

### Citations/bibliography
- **D-05:** A single **global `references.bib` file** (standard BibTeX format) at the project root holds all reference data — not per-post frontmatter lists. Matches the user's existing LaTeX/BibTeX authoring workflow.
- **D-06:** Authoring syntax in post Markdown is **`\cite{key}`** (LaTeX-familiar), not the pandoc-style `[@key]` syntax the underlying citation plugin natively expects. A small custom translation step rewrites `\cite{key}` into the plugin's native syntax before the citation plugin runs — same precedent as the existing custom `rehype-sequential-ids.mjs` plugin already in this codebase.
- **D-07:** Use the established citation-processing plugin (**`rehype-citation`**, built on `citation-js`) for parsing the `.bib` file, formatting citation marks, and generating the references list — not a hand-rolled citation formatter.
- **D-08:** Each post gets a numbered, auto-generated **"References" section** built from only the citations actually used on that specific page (not a dump of the entire global bibliography).

### Callout/note blocks
- **D-09:** Authored as fenced **directive containers**: `:::note`, `:::warning`, `:::tip` open the block, a bare `:::` on its own line closes it — explicit, user-controlled start and end, no auto-closing or implicit scope inference. Uses the standard `remark-directive`-family container syntax (the established Markdown-ecosystem approach for this).
- **D-10:** Three variants only for now: **note, warning, tip**. Simple bordered/colored box, consistent with the site's minimal aesthetic — no icons, no client JS.

### Definition blocks
- **D-11:** Same fenced-directive mechanism as callouts — `:::definition` ... `:::`, explicit start/end markers. The user specifically confirmed they want explicit control over where these blocks start and stop (see `<specifics>`), which is exactly what this syntax already provides.
- **D-12:** Plain styled block (term + definition text), **no interactive hover/tooltip mechanic** — avoids adding client JS for something the zero-JS-by-default site doesn't otherwise need.

### Claude's Discretion
- Exact rewritten DSGN-01 guard-test mechanism (D-04) — technical implementation, not a user-facing decision, as long as the "no marketing imagery" intent survives.
- Exact visual styling (colors/borders/spacing) for the three callout variants and definition blocks, within the existing minimal token system (`--bg`, `--surface`, `--accent`, `--text`, `--muted`) — no specific look was locked beyond "simple bordered/colored box."
- Whether citation numbering resets per-post vs. runs globally across the site — standard per-post numbering (the LaTeX convention) assumed unless it looks wrong in practice once there's real content.
- Any additional callout variants beyond note/warning/tip, if a real need shows up while writing — not locked now; keep the set small per the user's explicit "don't make it too complicated" guidance.
