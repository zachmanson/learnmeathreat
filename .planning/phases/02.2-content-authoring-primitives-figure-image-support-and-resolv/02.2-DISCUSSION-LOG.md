## Figures/images & DSGN-01 fix

| Option | Description | Selected |
|--------|-------------|----------|
| SVG (vector) + PNG/JPG (raster), no PDF | PDF cannot render as a web `<img>`; author re-exports vector figures as SVG instead | ✓ |
| Auto-invert SVG line art in dark mode via CSS filter | Avoids uploading two versions of every diagram | ✓ |
| Upload two image versions (light + dark) | Rejected — more manual work per figure, user explicitly wanted to avoid this | |

**User's choice:** SVG/PNG/JPG formats, CSS-filter dark-mode invert for SVG only, one `<Figure>` component with caption + auto-numbering (LaTeX figure-environment style). DSGN-01's existing "zero `<img>`" guard test (Test 22 in `02-03-PLAN.md`) must be rewritten to allow content figures while still blocking marketing/hero imagery.
**Notes:** User's original question was whether dark-mode inversion was possible without uploading two image versions — confirmed yes, via CSS `filter: invert(1)` applied to SVG figures with black-on-transparent line art. PNG/JPG raster images are excluded from inversion.

## Citations/bibliography

| Option | Description | Selected |
|--------|-------------|----------|
| Per-post frontmatter citation list | Simpler to build, no new file format | |
| Single global `.bib` file + `rehype-citation` plugin, `\cite{key}` syntax via translation layer | Matches user's actual LaTeX/BibTeX workflow | ✓ |

**User's choice:** One global `references.bib` file at project root. Author with `\cite{key}` (LaTeX-familiar); a small custom plugin translates this to the `rehype-citation` plugin's native `[@key]` syntax before it runs. Auto-generated, numbered "References" section per post, built only from citations actually used on that page.
**Notes:** Initial proposal was per-post frontmatter citation lists — user explicitly rejected this in favor of "something closer to LaTeX's bib" with one `.bib` file holding raw reference data, cited by ID anywhere via `\cite{}`.

## Callout/note blocks

| Option | Description | Selected |
|--------|-------------|----------|
| Fenced directive containers (`:::note` ... `:::`) | Standard Markdown-ecosystem pattern (remark-directive family), explicit start/end | ✓ |
| Note, warning, tip (3 variants) | Small, minimal set matching site aesthetic | ✓ |

**User's choice:** `:::note`, `:::warning`, `:::tip` fenced blocks, explicit closing `:::`, simple bordered/colored box, no icons or client JS.
**Notes:** User confirmed they specifically want explicit control over where these blocks start and stop — the fenced syntax already provides this natively.
