# `\label`/`\ref` use one flat global namespace, resolved via a two-pass build

Definitions and headings needed to be referenceable across posts (the series builds concept on concept, so a later post should be able to say "recall the definition of elliptic curve" and link back). Since `\label{key}`/`\ref{key}` never declare which element type or post they belong to (kept deliberately LaTeX-plain, matching the existing `\cite{key}` precedent), the only way to resolve a bare `\ref{key}` is a single global `key → location` map built by scanning every post's labels before any post's refs are resolved — a two-pass build, not the purely per-file remark pipeline every other authoring primitive (figures, citations, callouts) currently uses.

A consequence worth flagging: **every label on the site shares one namespace**, including equation and figure labels that are only ever referenceable from their own post. An equation label in post 3 and a figure label in post 7 still collide if they reuse the same key, even though neither could legally `\ref` the other. This was chosen over a type-scoped namespace (`\ref{def:foo}` vs `\ref{eq:foo}`) to keep authoring syntax exactly as simple as `\cite{key}` already is. Considered acceptable for the site's expected scale (a personal blog, not hundreds of labels); revisit with a type-prefix convention if key collisions become a real problem.
